# Архитектура blueprint

## Цель

`pi-project-blueprint` — шаблон проекта для Pi Coding Agent: набор правил, workflow и ресурсов, которые переносятся в целевой проект и управляют его разработкой.

## Разделение ответственности

```
rules/          Общие правила (stack-agnostic). Не ссылаются на Java/Spring/инструменты.
workflow/       Оркестратор: этапы, решения, gates. Не содержит проектных деталей.
agents/         Определения ролей (subagents) — см. docs/roles.md.
skills/         Навыки (SKILL.md) — специализированные инструкции по требованию.
prompts/        Промпт-шаблоны — slash-команды для запуска шагов/воркфлоу.
openspec/       Конвенции и шаблоны OpenSpec-артефактов.
install/        Сценарий неразрушающей установки в целевой проект.
stacks/         Проектные профили (опционально). Единственное место, где может появиться Java/Spring.
docs/           Мета-документация: архитектура, роли, workflow, конфигурация моделей.
```

Правило: **ни один файл в `rules/`, `workflow/`, `openspec/` не должен предполагать стек или набор инструментов целевого проекта.** Всё стек-специфичное выносится в `stacks/<профиль>/`.

## Соответствие механизмам Pi (проверено)

Источники: документация Pi (`docs/` в установке) и исходники окружения (`~/.pi/agent/extensions/subagent/`).

### Проектная конфигурация `.pi/`

Целевой проект настраивается через каталог `.pi/` в корне проекта:

| Путь | Назначение |
|---|---|
| `.pi/settings.json` | Проектные настройки и пути к ресурсам. Проектные настройки перекрывают пользовательские; списки ресурсов объединяются. |
| `.pi/APPEND_SYSTEM.md` | Добавляет инструкции к системному промпту (для проекта). |
| `.pi/SYSTEM.md` | Полностью заменяет системный промпт (для проекта). |
| `.pi/extensions/` | Проектные расширения. |
| `.pi/skills/` | Проектные навыки. |
| `.pi/prompts/` | Проектные промпт-шаблоны (slash-команды). |
| `.pi/agents/` | Проектные subagents (обнаруживаются расширением subagent). |

### Subagents

- Формат: Markdown-файл с frontmatter (`name`, `description`, `tools`, `model`) и телом = системный промпт агента.
- Расположение: пользовательские `~/.pi/agent/agents/`, проектные `.pi/agents/` (поиск вверх по дереву до корня репозитория).
- Поле `tools` — список через запятую. Поле `model` — необязательное.
- Инструмент `subagent` поддерживает три режима:
  - **single** — один агент, одна задача;
  - **parallel** — массив задач (до 8 задач, параллелизм до 4);
  - **chain** — последовательность с передачей вывода предыдущего шага через плейсхолдер `{previous}`.
- Область видимости агентов: `user` / `project` / `both` (параметр `agentScope`).
- Ограничения (из исходников расширения): `MAX_PARALLEL_TASKS = 8`, `MAX_CONCURRENCY = 4`, лимит вывода на задачу `50 KB`.
- Каждый вызов subagent порождает отдельный процесс `pi` в JSON-режиме → изолированный контекст.

### Skills

- Каталог с `SKILL.md`, frontmatter `name` + `description`, опционально `disable-model-invocation`, `allowed-tools`, `license`, `metadata`.
- Загружаются по требованию (по описанию), не держат инструкции в контексте постоянно.
- Расположение: `~/.pi/agent/skills/` или `.pi/skills/` (также `.agents/skills/`).

### Prompt templates

- Markdown в `prompts/`, имя файла → `/имя` команда. Поддержка `$1`, `$@`, `${1:-default}`.
- Расположение: `~/.pi/agent/prompts/` или `.pi/prompts/`.

### Контекст-файлы

- `AGENTS.md` / `CLAUDE.md` загружаются автоматически из рабочего каталога и родительских; `AGENTS.override.md` заменяет `AGENTS.md` в том же каталоге. Не требуют доверия к проекту.

### Пакеты

- `pi install git:...` / `npm:...` / локальный путь; пакет может собирать extensions/skills/prompts/themes. Возможный путь дистрибуции blueprint — но требует отдельного решения (см. ниже).

## Проверенные факты vs неизвестное

### Проверено

- Расположение и формат проектных настроек, skills, prompts, agents, контекст-файлов.
- Режимы subagent-инструмента и его ограничения (см. выше).
- OpenSpec — это `@fission-ai/openspec` (источник: github.com/Fission-AI/openspec). Установлен CLI **1.14.0**. Ключевые команды: `new change`, `status --change`, `instructions <artifact> --change`, `list`, `show`, `validate`, `archive`, `context`, `schemas`, `config`, `store`.
- **OpenSpec нативно поддерживает Pi**: `openspec init --tools pi` генерирует slash-команды `/opsx:*` в `.pi/prompts/opsx-<id>.md` (id `pi` есть в списке `openspec init --help`).
- Устаревшие команды из пользовательского skill `openspec` (`openspec generate`, `openspec update-version`) в CLI 1.14.0 **отсутствуют** — skill подлежит сверке с актуальным CLI.

### Неизвестно / требует решения

1. **subagent-расширение не встроено в Pi.** Оно установлено пользовательски (`~/.pi/agent/extensions/subagent/`). Blueprint зависит от него — нужно решить: поставлять его копию, объявлять как предусловие или упаковать в пакет.
2. **Модели в subagents.** Спроектировано разделение «роль ≠ модель» и уровни `cheap/medium/expensive` как логическая конфигурация (см. `docs/model-configuration.md`). Открытым остаётся точное имя/формат файла переопределений проекта — решается на этапе установщика.
3. **Способ дистрибуции:** Pi-пакет (`pi install`) vs копирование файлов vs агентная установка по сценарию. Решается на этапе `install/`.
4. **OpenSpec bootstrap:** корень создаётся через `openspec init --tools pi` (не как побочный эффект `openspec new change`). Правило blueprint: не инициализировать без явной просьбы пользователя.
5. **Мерж настроек:** `settings.json` целевого проекта нужно **дополнять**, а не перезаписывать; точная стратегия мержа — в `install/`.
