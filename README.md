# pi-project-blueprint

Переиспользуемый набор правил и инструментов для настройки **Pi Coding Agent** в новых проектах.

> **Статус:** этап 2 — спроектированы роли, workflow и конфигурация моделей (документация). Установщик и файлы subagents пока **не реализованы**.

## Назначение

В будущем я буду передавать Pi ссылку на этот репозиторий, а он должен уметь:

1. Изучить этот репозиторий (правила, workflow, роли, конвенции OpenSpec, конфигурацию моделей).
2. Проанализировать целевой проект.
3. Настроить целевой проект по правилам blueprint **без перезаписи** существующих настроек Pi и без изменений в других проектах.
4. Вести задачу через управляемый workflow: анализ → OpenSpec-планирование → ручное согласование → реализация → независимые ревью/QA → приёмка → архивирование.

## Ключевые понятия

- **Роли команды** (`docs/roles.md`): `analyst`, `architect`, `developer`, `code-reviewer`, `qa`, `devops` — реализуются как project-local subagents. `orchestrator` — основной Pi-агент, не subagent.
- **Workflow** (`docs/workflow.md`, `workflow/orchestrator.md`): 10 этапов, два обязательных ручных gate (A — согласование плана, B — приёмка результата).
- **Модели по уровням стоимости** (`docs/model-configuration.md`): `cheap` / `medium` / `expensive` — наша логическая конфигурация, разрешаемая в реальные модели при установке. Роль и модель разделены.
- **OpenSpec** (`openspec/`): артефакты `proposal.md`, `specs/`, `design.md`, `tasks.md`; источник правил — [Fission-AI/openspec](https://github.com/Fission-AI/openspec).

## Структура репозитория

| Каталог | Назначение |
|---|---|
| [`rules/`](rules/) | Общие инструкции и правила, **не зависящие от стека** (контекст-файл `AGENTS.md`). |
| [`workflow/`](workflow/) | Workflow оркестратора: этапы, решения, обязательные gates. |
| [`agents/`](agents/) | Роли → определения subagents (`.pi/agents/*.md`). Пока — конвенции и состав. |
| [`skills/`](skills/) | Навыки (SKILL.md) для установки в проект. Пока — только конвенции. |
| [`prompts/`](prompts/) | Промпт-шаблоны (slash-команды). Пока — только конвенции. |
| [`openspec/`](openspec/) | Интеграция с OpenSpec: конвенции, шаблоны артефактов. |
| [`install/`](install/) | Инструкция и сценарий установки blueprint в другой проект (будущее). |
| [`stacks/`](stacks/) | **Проектные профили** (например, Java/Spring). Отделены от общих правил. |
| [`docs/`](docs/) | Документация: архитектура, роли, workflow, конфигурация моделей. |

## Принцип разделения

- **Общие правила** (`rules/`, `workflow/`, `openspec/`) — применимы к любому проекту, не предполагают Java/Spring/конкретный набор инструментов.
- **Проектные настройки** (`stacks/`) — опциональные профили под конкретный стек.
- **Исполняемые ресурсы** (`agents/`, `skills/`, `prompts/`) — то, что копируется/мержится в `.pi/` целевого проекта.

## Как будет работать установка (будущее)

Pi получает ссылку на репозиторий, изучает `install/scenario.md`, анализирует целевой проект и выполняет **неразрушающую** настройку: копирует роли в `.pi/agents/`, мержит `settings.json`, проверяет предварительные требования (subagent-расширение, OpenSpec CLI), разрешает ценовые уровни в реальные модели (`pi --list-models`). Подробнее: [`install/README.md`](install/README.md).
