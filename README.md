# pi-project-blueprint

Переиспользуемый набор правил и инструментов для настройки **Pi Coding Agent** в новых проектах.

> **Статус:** этап 1 — спроектирована и создана базовая структура. Установщик и определения subagents пока **не реализованы**.

## Назначение

В будущем я буду передавать Pi ссылку на этот репозиторий, а он должен уметь:

1. Изучить этот репозиторий (правила, workflow, определения subagents, конвенции OpenSpec).
2. Проанализировать целевой проект.
3. Настроить целевой проект по правилам blueprint **без перезаписи** существующих настроек Pi и без изменений в других проектах.
4. Прогнать задачу через управляемый workflow: анализ → OpenSpec-планирование → ручное согласование → реализация → независимое ревью → тестирование → приёмка и архивирование.

## Структура репозитория

| Каталог | Назначение |
|---|---|
| [`rules/`](rules/) | Общие инструкции и правила, **не зависящие от стека** (контекст-файл `AGENTS.md`). |
| [`workflow/`](workflow/) | Workflow оркестратора: этапы, решения, обязательные gates. |
| [`agents/`](agents/) | Определения subagents (проект-локальные, `.pi/agents/*.md`). Пока — только конвенции и план. |
| [`skills/`](skills/) | Навыки (SKILL.md) для установки в проект. Пока — только конвенции. |
| [`prompts/`](prompts/) | Промпт-шаблоны (slash-команды). Пока — только конвенции. |
| [`openspec/`](openspec/) | Интеграция с OpenSpec: конвенции ведения артефактов, шаблоны. |
| [`install/`](install/) | Инструкция и сценарий установки blueprint в другой проект (будущее). |
| [`stacks/`](stacks/) | **Проектные профили** (например, Java/Spring). Отделены от общих правил. |
| [`docs/`](docs/) | Документация: архитектура, workflow, план реализации. |

## Принцип разделения

- **Общие правила** (`rules/`, `workflow/`, `openspec/`) — применимы к любому проекту, не предполагают Java/Spring/конкретный набор инструментов.
- **Проектные настройки** (`stacks/`) — опциональные профили под конкретный стек, подключаются только если проект им соответствует.
- **Исполняемые ресурсы** (`agents/`, `skills/`, `prompts/`) — то, что копируется/мержится в `.pi/` целевого проекта.

## Как будет работать установка (будущее)

Кратко: Pi получает ссылку на репозиторий, изучает `install/scenario.md`, анализирует целевой проект и выполняет **неразрушающую** настройку — копирует ресурсы в `.pi/`, мержит `settings.json` (не перезаписывает), проверяет предварительные требования (subagent-расширение, OpenSpec CLI). Подробнее: [`install/README.md`](install/README.md) и [`install/scenario.md`](install/scenario.md).

## План дальнейшей реализации

1. ~~Спроектировать и создать базовую структуру~~ (текущий этап).
