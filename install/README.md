# Установка blueprint в целевой проект

> **Статус:** только проект сценария. Установщика, генератора моделей и готовых определений subagents нет; текущий репозиторий не является готовым установочным пакетом.

Канонический [сценарий установки](scenario.md) предусматривает исследование, план, **явное подтверждение до любой записи**, применение только согласованных изменений и отчёт. Это отдельная процедура настройки, не альтернативная нумерация [workflow разработки](../docs/workflow.md).

## Принципы

- Не изменять другие проекты или `~/.pi/agent/`; глобальная настройка/установка зависимостей требует отдельной просьбы.
- Существующие настройки, роли, инструкции и ресурсы сохраняются. Любое дополнение/слияние тоже является записью и требует согласованного diff; конфликт не разрешается молчаливой перезаписью.
- Не запускать `openspec init` автоматически. Пользователь отдельно решает, нужна ли инициализация. Не обходить это через `openspec new change`.
- Проверять доступность моделей и зависимостей насколько возможно; не обещать успешный API-запрос только по каталогу.
- Различать установленное, неподдерживаемое, пропущенное и требующее ручных действий.

## Что предполагается доставлять

| Источник | Предлагаемое назначение в целевом проекте |
|---|---|
| `rules/AGENTS.md` | Согласованный блок в корневом `AGENTS.md`; не слепая замена и не `.pi/AGENTS.md` |
| `workflow/orchestrator.md` и необходимые `docs/`/конвенции OpenSpec | Инструкции основной сессии и справочные материалы с проверенными ссылками; layout доставки ещё согласуется |
| Будущие `agents/<role>.md` | Шесть `.pi/agents/<role>.md`, явные модели по проектному источнику |
| Будущие реальные навыки/промпты из `skills/`, `prompts/` | `.pi/skills/`, `.pi/prompts/`; README-конвенции не устанавливаются как skills/команды |
| Будущий выбранный профиль `stacks/<name>/` | Только совместимые и согласованные ресурсы; готовых профилей пока нет |
| Будущий `config/models.yaml` | Вход генератора пресетов; проектные назначения предлагаются в `.pi/blueprint-models.yaml`, defaults основной сессии — в `.pi/settings.json` |

`openspec/config.example.yaml` — справочный шаблон, не готовая конфигурация проекта; его нельзя копировать поверх существующего `openspec/config.yaml`. Инициализация OpenSpec и создание его prompt-команд не имитируются установщиком.

## Предварительные требования

| Проверка | Если отсутствует/неподтверждено |
|---|---|
| Версия Pi и совместимый Node.js | Сообщить; локальная документация Pi 1.1.0 требует Node.js 22.19+, OpenSpec 1.14.0 — 20.19+; требования выбранных версий проверяются отдельно |
| Совместимое расширение subagent, его источник и интерфейс | Остановить настройку ролей; предложить отдельно согласовать установку/версию, не копировать неизвестное расширение |
| OpenSpec CLI (`openspec --version`) | Предложить инструкцию установки выбранной версии; не выполнять глобальный `npm install` автоматически |
| Корень OpenSpec (`openspec context --json`) | Сообщить фактический root/store; при отсутствии спросить об инициализации, при внешнем root — об отдельном разрешении записи |
| Модели (`pi --list-models`, при поддержке — безопасная проверка auth) | Попросить выбрать доступные ID или настроить провайдера вручную; не сохранять выдуманную замену |
| Доверие к проекту и ресурсам дочернего Pi | Пояснить пользователю различие project trust и подтверждения subagents; не включать доверие молча |

Решения по доставке, обновлению, YAML и безопасному QA: [docs/architecture.md](../docs/architecture.md). Назначения моделей: [docs/model-configuration.md](../docs/model-configuration.md).
