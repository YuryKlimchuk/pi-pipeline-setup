# Установка blueprint в новый проект

> **Статус:** установщик **не реализован**. Этот документ описывает, как установка **будет** работать.

## Цель

Перенести правила, workflow и ресурсы blueprint в целевой проект **неразрушающе**:

- не перезаписывать существующие настройки Pi в проекте;
- не трогать пользовательские настройки (`~/.pi/agent/`);
- не изменять другие проекты.

## Будущий сценарий использования

Пользователь в целевой проект запускает Pi и передаёт ссылку на этот репозиторий. Pi:

1. Изучает `README.md`, `install/scenario.md` и структуру blueprint.
2. Анализирует целевой проект: наличие `.pi/`, `AGENTS.md`, OpenSpec-корня, стека (для выбора профиля из `stacks/`).
3. Проверяет предварительные требования (см. ниже).
4. Выполняет неразрушающую настройку по сценарию.
5. Отчитывается, что сделано и что осталось решить пользователю.

## Предварительные требования (проверяются при установке)

| Требование | Проверка | Действие, если нет |
|---|---|---|
| subagent-расширение | наличие `subagent` tool / расширения | установить или объявить предусловием (*открытое решение*) |
| OpenSpec CLI | `openspec --version` | `npm install -g @fission-ai/openspec@latest` |
| OpenSpec в проекте | `openspec context --json` → `root` | `openspec init --tools pi` (только с явного согласия) |
| Node.js 20.19+ (для OpenSpec) | `node --version` | сообщить пользователю |

## Что переносится

| Источник blueprint | Назначение в проекте |
|---|---|
| `rules/AGENTS.md` | контекст-файл `AGENTS.md` (в корень или `.pi/`) — общие правила |
| `workflow/orchestrator.md` | инструкция оркестратора (через контекст-файл или промпт-шаблон) |
| `agents/*.md` | `.pi/agents/*.md` (subagents) |
| `skills/**` | `.pi/skills/**` |
| `prompts/*.md` | `.pi/prompts/*.md` (slash-команды) |
| `openspec/conventions.md`, `templates/` | справочные конвенции и шаблоны OpenSpec (не копируются в проект; служат инструкциями для агентов) |
| `stacks/<профиль>/**` | только выбранный профиль (если стек совпал) |

## Правила неразрушающей установки

1. Существующие файлы с тем же именем **не перезаписывать** — либо пропустить с предупреждением, либо мержить по явной стратегии.
2. `settings.json` — **дополнять** (ресурсы объединяются), не заменять.
3. Не запускать `openspec init` без явной просьбы пользователя.
4. Любое сомнительное действие — спросить, а не выполнять.

## Открытые вопросы

- Способ дистрибуции: Pi-пакет (`pi install git:...`) vs прямое копирование vs агентная установка.
- Стратегия мержа `settings.json` и контекст-файлов при конфликтах.
- Порядок применения профиля из `stacks/`.
