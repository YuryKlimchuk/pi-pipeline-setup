# Сценарий установки в целевой проект

> Это **описание будущего** сценария, который реализует установщик. На текущем этапе сценарий не выполняется автоматически.

## Шаг 0 — Получить и понять запрос

- Пользователь даёт ссылку на blueprint и просит настроить проект.
- Прочитать `README.md` blueprint и этот сценарий.

## Шаг 1 — Анализ целевого проекта

Собрать факты (только чтение):

- Есть ли `.pi/`? Какие файлы уже настроены (`settings.json`, `SYSTEM.md`, `APPEND_SYSTEM.md`, `agents/`, `skills/`, `prompts/`)?
- Есть ли `AGENTS.md` / `CLAUDE.md`? Что в них?
- Есть ли OpenSpec-корень? (`openspec context --json`)
- Какой стек/инструменты? (для выбора профиля `stacks/`; при неопределённости — спросить)
- Доступны ли `subagent` tool и `openspec` CLI?

## Шаг 2 — Проверка предварительных требований

- `node --version` ≥ 20.19 (требование OpenSpec).
- `openspec --version` — если нет, сообщить: `npm install -g @fission-ai/openspec@latest` (с согласия).
- OpenSpec-корень в проекте (`openspec context --json` → `root`) — если нет, предложить `openspec init --tools pi` (генерирует `openspec/` и slash-команды `/opsx:*` в `.pi/prompts/`); не запускать без явного согласия.
- subagent-расширение — если нет, следовать принятому решению (см. `docs/architecture.md`, открытые вопросы).
- Доступные модели — `pi --list-models`; записать фактически доступные (см. ниже).

## Шаг 3 — Составить план переноса

Сформировать список «источник → назначение» с учётом неразрушающих правил (`install/README.md`). Показать план пользователю, отметить конфликты с существующими файлами.

Сюда же входит **конфигурация моделей** (`docs/model-configuration.md`):
- выбрать профиль (`economy` / `balanced` / `max-quality`) или назначения по умолчанию;
- разрешить уровни `cheap/medium/expensive` в конкретные ID моделей по `pi --list-models`;
- зафиксировать персональные переопределения ролей;
- проверить доступность каждой выбранной модели и показать результат пользователю.

## Шаг 4 — Выполнить перенос

- Копировать роли в `.pi/agents/`, записывая в `model:` фронтматтер разрешённые ID моделей.
- Дополнить `settings.json` (не перезаписывать).
- Разместить общие правила (контекст-файл).
- Применить выбранный профиль `stacks/` (если есть).

## Шаг 5 — Верификация и отчёт

- Проверить, что ресурсы обнаружены (например, запуск Pi и `/reload`, список агентов).
- Сообщить: что установлено, что пропущено/мержено, что требует решения пользователя.

## Шаг 6 — Документировать в проекте

- Добавить в проект краткую запись о подключении blueprint (что настроено, версия/commit blueprint).

> Конкретные команды и точная стратегия мержа определяются на этапе реализации установщика.
